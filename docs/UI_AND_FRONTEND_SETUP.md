# FairPass 界面说明与前端启动指南

本文给第一次拿到仓库的同学使用：先说明学生、主办方和验票员在界面中分别做什么，再说明如何在自己电脑上启动前端。当前仓库**前端已可运行，后端和 Fabric 链码尚未实现**。不连接后端时看到的是界面预览，不能当作真实票务系统使用。业务规则和接口字段另见 [共同契约](SHARED_CONTRACT.md)与 [HTTP API v1](API_V1.md)。

## 一、三个身份如何使用界面

页面右上角的「账户」菜单用于查看当前身份。**界面预览模式**下，可在这里切换学生、主办方、验票员；**真实 API 模式**下，输入后端提供的测试账号登录，身份由服务端返回，页面不会提供随意切换角色的入口。

### 学生：发现活动、报名、领票和使用门票

| 界面 | 学生在这里做什么 | 页面上会看到什么 |
|---|---|---|
| 「活动」 | 浏览活动，打开感兴趣的活动详情 | 活动标题、简介、地点、开始时间、报名截止时间及当前状态；活动较多时可翻页 |
| 活动详情 | 在报名截止前报名；抽签发布后根据结果领票 | 活动信息与当前阶段相符的主要操作。报名成功只是获得抽签资格，不等于持票；未中签者不能领票 |
| 「我的报名」 | 集中查看已报名活动的进度 | 「已报名／等待抽签」「已中签」「未中签」；已中签且尚可领票时出现领票入口 |
| 「我的门票」 | 查看当前持有的票并准备入场 | 可在堆叠视图与平铺视图间切换；堆叠视图可切到下一张票，打开票后可翻到背面 |
| 门票背面 | 出示二维码或完整票号，并查阅票务信息 | 活动时间、地点、当前票号、持有人、已确认链上流转记录和交易 ID；可关闭背面返回票堆 |
| 转让窗口 | 在活动开始前把尚未核销的票转给另一名学生 | 输入接收方学生 UUID，确认活动、票号和接收方。v1 每张票最多转让一次；真实转让确认后，原持有人不再在「我的门票」中看到这张票 |
| 「待接收门票」 | 查看当前版本对转入票的说明 | v1 转让在转出方确认后直接变更归属，没有接受/拒绝邀请流程；此页目前是说明性空状态 |

学生的典型路径是：**活动 → 活动详情 → 报名 → 我的报名查看抽签结果 → 中签后领票 → 我的门票 → 翻面出示二维码**。转让是持票后的可选操作，不是报名或领票的必要步骤。现场验票时，应出示票背二维码或完整票号；是否有效由后端和链码确认，不能只凭前端显示判断。

### 主办方：创建活动、发布抽签和查看记录

| 界面 | 主办方在这里做什么 | 页面上会看到什么 |
|---|---|---|
| 「活动管理」 | 查看自己创建的活动并进入管理详情 | 本人活动列表、时间、地点、状态和「创建活动」入口；真实模式由 `/me/events` 返回本人活动及分页总数 |
| 创建活动抽屉 | 填写活动内容和票数规则 | 标题、简介、地点、名额、报名截止、活动开始/结束时间；真实创建只有在链上确认后才算成功 |
| 活动管理详情 | 掌握报名和发票进度 | 名额、报名人数、中签人数、已领票、已核销数量，以及活动时间地点和当前状态 |
| 活动抽签区域 | 在报名截止后、活动开始前发布一次抽签 | 符合条件时可开始抽签；处理中保持只读；完成后显示中签人数和交易 ID，不可再次执行 |
| 「链上记录」 | 核对该活动已确认的关键操作 | 创建活动、抽签发布、领票、转让、核销的时间线；支持按类型筛选、分页和查看交易详情。报名本身属于平台记录，不是链上交易 |

主办方只管理自己创建的活动。抽签结果以已确认的服务端和链上状态为准；界面不会自行选出中奖者。

### 验票员：查票、复核和核销入场

| 界面 | 验票员在这里做什么 | 页面上会看到什么 |
|---|---|---|
| 扫码/输入票号 | 读取学生票背二维码，或手动输入完整票号 | 有摄像头和浏览器扫码能力时可扫码；否则使用手动输入。提交后先查询票，不会立即核销 |
| 门票复核 | 在真正放行前检查信息 | 活动、活动时间、当前持有人、完整票号和票状态；确认无误后点击「确认核销」 |
| 核销结果 | 判断是否可以放行，并继续检查下一张票 | 真实成功时显示核销信息及本次已确认交易 ID；已核销、时间不符或其他失败会单独提示，不能再次放行；可返回继续扫码 |

验票流程是 **先查询 → 人工复核 → 确认核销 → 看到成功结果后放行**。请求超时或 Fabric 状态不明时，页面不会直接宣布入场成功；应重新查询票状态并核对记录。

## 二、先区分预览与真实 API

| 运行方式 | 如何启用 | 能验证什么 | 不代表什么 |
|---|---|---|---|
| 界面预览 | 不设置 `VITE_API_BASE_URL` | 三种身份的页面、文案、交互、票堆与翻牌动画、表单布局 | 没有真实报名、中签、票权、链上交易或入场资格 |
| 真实 API | 在 `frontend/.env.local` 设置 `VITE_API_BASE_URL`，并启动兼容 v1 契约的后端和 Fabric | 使用后端测试账号联调实际业务流程 | 目前仓库还没有可运行的后端和链码，因此暂时不能仅靠本仓库跑通真实流程 |

预览页顶部会标注「界面预览 · 示例数据 · 门票不可用于入场」。预览中的报名和创建活动只改变本地示例状态；「预览抽签」只展示可抽人数，不选出中奖者；转让不会改变真实归属；验票示例 `demo-ticket-after-hours` 不核销也不放行；门票二维码、哈希和链上记录不构成真实交易凭证。

## 三、其他同学拿到代码后如何启动前端

准备：电脑安装 Git、Node.js 和 npm。当前项目使用的 Vite 6 要求 Node.js 18、20 或 22 及更新的兼容版本，团队可统一使用 Node.js 20 或 22。在终端执行 `git --version`、`node --version`、`npm --version`，确认命令可用。项目依赖由 `frontend/package.json` 和 `frontend/package-lock.json` 管理；前端使用 React、TypeScript、Vite。**运行命令的位置是仓库的 `frontend/` 目录，不是仓库根目录。**

首次拉取并启动（PowerShell、macOS Terminal 或 Linux shell 中均可逐行运行）：

```sh
git clone https://github.com/k0mondor/fairpass.git
cd fairpass/frontend
npm ci
npm run dev
```

`npm ci` 根据已提交的 lockfile 安装依赖，适合团队使用；依赖会放入 `frontend/node_modules/`，不用提交到 Git。终端会打印本地地址，**打开它实际输出的地址**（通常是 `http://127.0.0.1:5173/`，端口占用时可能不同）。保持终端运行才能访问页面，停止用 `Ctrl+C`。初次启动不需要后端、不需要 Docker，也不需要填写 `.env.local`；此时进入界面预览。点击右上角「账户」→「切换预览角色」依次查看三种工作界面。

如果 Windows PowerShell 提示 `npm.ps1` 被执行策略拦截，使用同目录下的 `npm.cmd ci` 和 `npm.cmd run dev`，不需要修改系统执行策略。

以后从已有仓库启动：

```sh
cd fairpass/frontend
npm run dev
```

拉取更新后，如果 `package-lock.json` 发生变化，再在 `frontend/` 运行一次 `npm ci`。如需验证能否打包，运行 `npm run build`；它会先检查 TypeScript，再由 Vite 生成 `frontend/dist/`。如需本地查看构建产物，运行 `npm run preview`。`node_modules/` 和 `dist/` 已被 Git 忽略。

### 后端完成后切换到真实数据

在 `frontend/` 把 `.env.example` 复制为 `.env.local`，将 `VITE_API_BASE_URL` 指向后端**包含 `/api/v1` 的完整前缀**，例如：

```dotenv
VITE_API_BASE_URL=http://127.0.0.1:3000/api/v1
```

修改环境变量后停止并重新执行 `npm run dev`。页面会进入测试账号登录，而不是三角色预览切换。测试账号名、后端端口、数据库初始化和 Fabric 启动步骤由后端/区块链同学交付；前端不会自行启动这些服务。若浏览器显示网络错误，先核对后端是否运行、URL 和端口是否一致，以及后端是否允许当前前端地址跨域访问。`.env.local` 是个人机器配置，不应提交。

联调时按 [API v1](API_V1.md) 核对接口。学生使用 `GET /events` 等接口，主办方列表使用 `GET /me/events`，验票成功必须拿到 `POST /tickets/:ticketId/redeem` 返回的 `{ ticket, operation }`，其中 `operation.txId` 是本次确认交易的 ID。
