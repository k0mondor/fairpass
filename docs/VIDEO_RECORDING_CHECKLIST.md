# FairPass 视频录制指南
制作了一些账号帮助演示，下文提到的人名即用户名
主线：**主办方morgan创建活动 → 学生alex和jamie报名 → 中签者领票并转给未中签者 → 验票账号taylor验票 → 查看记录**

建议成片约四五分钟，要是比较短可以顺便解说一下页面里的其他细节。可以先录屏，再配音或者做字幕。每次操作成功后停留两三秒，登录、输入和等待过程可以剪短

## 开拍前

- 按 [项目说明](../README.md) 启动；正式展示链上功能使用真实Fabric环境，麻烦老师配置一下环境
- 账号：morgan选“主办方”，alex和jamie选“学生”，taylor选“验票员”。密码都是 `123456`。换人时先退出登录
- 新建一场活动，名额设为 **1**，让 **alex和jamie都报名**。两人中随机选一人中签，另一人未中签
- 时间按创建当时填写：报名截止为 **5分钟后**，活动开始为 **30分钟后**，结束为 **90分钟后**。验票在开场前30分钟开放，领票和转让必须在开场前完成

**抽签结果不能预先指定。** 下文按alex中签举例；如果jamie中签，就由jamie领票并转给alex，配音里的名字也一起调换

## 1. morgan创建活动

**操作：** morgan登录 →“活动管理”→“创建活动”。名称填“校园音乐会 · 视频演示”，地点填“校园大礼堂”，名额填1，时间按自己需要的填写
提交后展示创建成功的页面

**解说：**

> 这是FairPass校园活动票务系统。登录主办方账号，主办方morgan先创建一场音乐会，设置一个门票名额，并填写报名和活动时间，活动描述等信息。

## 2. alex和jamie分别报名

**操作：** alex登录 → 打开这场音乐会 →“报名活动”。再换jamie登录，对同一场活动报名。换回morgan，展示报名人数为2、名额为1
也可以展示学生界面的三个界面并简易展示其设计和功能 然后我的门票这个界面我做了比较有趣的小动效 也可以放在视频里

**解说：**

> 学生alex和jamie都报名参加。现在有两个人报名，但只有一个名额，需要在报名截止后抽签。

## 3. 抽签，中签者领取门票

**操作：** 报名截止后，morgan打开活动详情 →“开始抽签”。分别登录两个学生账号，在“我的报名”中展示一人中签、一人未中签。再由中签者点击“领取门票”，打开“我的门票”，展示票卡和背面的票号，也可以展示门票后面的哈系等链上信息

把完整票号复制保存，后面验票用同一个。等待报名截止的过程剪掉，字幕标“报名截止后”

**解说（alex中签时）：**

> 报名截止后，morgan发布抽签结果。这次alex中签，jamie未中签。alex领取门票后，就能在“我的门票”中查看活动信息、票号和二维码

## 4. 把票转给未中签的同学

**操作：** alex打开这张票 →“转让门票”→输入 `jamie` →核对信息 →“确认转让”。成功后，换jamie登录，展示收到的门票；核对转让前后的票号相同

**解说：**

> 假设alex临时无法参加，他可以把票转给没有中签的jamie。转让后，alex不再持有这张票，jamie可以在自己的账号里看到它。票号不变，持有人发生了变化。每张票在开场前最多转让一次

## 5. taylor验票

**操作：** taylor登录 →“活动验票”→输入刚才保存的完整票号 →“查询门票”
展示活动、当前持有人和门票状态，再点“确认核销”。成功后重新查询同一票号，展示“已核销”

**解说：**

> 入场前，验票员taylor查询这张票，核对活动、持有人和有效状态，再确认核销。核销成功表示这张票已经用于入场。再次查询时，它已是核销状态，不能重复使用

## 6. 查看记录，结束

**操作：** morgan登录 → 打开同一场音乐会 → 展示报名2人、中签1人、已领票1、已核销1。
进入“链上记录”，展示创建、抽签、领取、转让和核销记录，再打开一条转让或核销详情，停在交易ID和区块号处

**解说：**

> 最后，morgan可以查看活动进展，以及创建、抽签、领票、转让和核销的链上记录。打开详情，还能查看对应的交易ID和区块号。这样，一张票从发放、转让到入场的过程就可以回头核对
