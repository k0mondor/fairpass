# FairPass 真实使用走查

本清单用于录制前由操作者检查实际功能。自动化回归使用模拟接口，不能替代本清单；本轮不提前领取、转让或核销正式演示票。

## 1. 启动与准备

1. 按 [本机环境说明](LOCAL_FABRIC_SETUP.md) 启动真实后端和Fabric，确认后端使用 `FABRIC_GATEWAY_MODE=real`。WSL运行的后端使用 `/opt/fairpass-dev/backend` 中的代码副本；如果后端代码有更新，需要重启仓库启动脚本重新同步。本次修改主要在前端，无需升级链码。
2. 在 `frontend/` 执行 `npm ci` 安装更新后的测试依赖，执行 `npm run dev`。`.env.local` 设置API地址及演示角色切换，详见 [录制清单](VIDEO_RECORDING_CHECKLIST.md)。现有Vite开发服务通常会热更新；配置变更需要重启。
3. 确认页面不是界面预览，真实操作历史没有 `mock-` 交易ID。不要仅用健康检查或ID长度作为真实网络工作的全部证据。
4. 本次新建“走查专场 + 日期/序号”，容量1，仅alex报名。报名截止设为当前时间后5分钟、开始后20分钟、结束后80分钟，按实际操作速度留出余量。界面时间统一标注UTC+8，与香港时间一致；API和账本仍保存UTC。

## 3. 可选异常体验检查

- 历史失败重试：先打开票，浏览器开发工具切离线，重新打开票背触发历史查询，应显示失败而不是“暂无记录”；恢复网络后点“重试查询”，应恢复记录。只做查询，不在离线时提交正式票务操作。
- 慢交易：真实网络较慢时应显示“交易仍在处理中”，按钮保持禁用；不要为测试而中断Fabric或修改系统时间。超过12秒的正常返回已由自动化测试模拟验证。
- 门票超过20张：自动化测试验证21张票的跨页加载与页面展示，不要求在真实链中额外创建21张测试票。
