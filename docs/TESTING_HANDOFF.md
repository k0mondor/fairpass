# 测试交接指南

## 1. 提交的数据范围

仓库保存代码、配置模板、演示账号定义与可重建的预置数据脚本。开发者手工创建的 `test` 活动、E2E活动、已操作门票、SQLite数据库、Fabric账本、私钥、登录token和 `.local/` 运行清单均不提交。同学首次启动会生成自己的数据，不会继承本机测试结果。

## 2. 无Fabric环境：可交互Mock测试

需要Node.js 22及npm。Windows使用PowerShell；若PowerShell禁止执行npm脚本，可将以下 `npm` 写作 `npm.cmd`。

终端一，在仓库的 `backend/` 中：

```powershell
npm ci
npm run demo:mock
```

等待打印 `READY: clean Mock demo`，首次准备约两分钟。该命令自动构建后端、初始化账号并启动API，使用独立SQLite数据库和内存Mock账本，准备四组校园展示活动及三组可交互场次。默认端口3000，端口被占用时先停止原服务。无需复制后端 `.env`，不会修改真实Fabric或已有数据库。

终端二，在仓库的 `frontend/` 中：

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev -- --strictPort
```

打开 `http://127.0.0.1:5173/`。配置模板将API指向 `http://127.0.0.1:3000/api/v1`，不填写时只是界面预览。若更改端口，需同步修改前端API地址及后端CORS配置。

停止Mock后内存账本消失；再次执行 `npm run demo:mock` 会创建全新的一组数据，避免旧SQLite与新Mock账本不一致。历史数据库仅留在被忽略的 `.local/mock-*/`，不会上传。登录密钥每次重新生成，重启后应重新登录。Mock交易ID以 `mock-` 开头、区块号为空，只用于功能测试，不能作为真实上链证据。

## 4. 开始操作的顺序

1. alex登录：“开放报名体验”尚未报名，可报名；“领票与转让体验”已中签但未领取，可领票，再输入 `jamie` 转让。
2. jamie登录：在“我的门票”检查收到的票及历史；重复转让应被拒绝。
3. alex登录：查看“现场验票体验”的预领票，复制票码；taylor登录查询该票并核销，再次核销应被拒绝。此场次已进入验票窗口且尚未核销，准备后有效约4小时。
4. morgan登录：自行创建新的活动，报名截止时间设为几分钟后；学生报名后等待截止，再由morgan发布抽签。报名截止必须晚于当前时间，且早于活动开始；结束晚于开始。实际操作时使用新时间，避免照抄旧截图。
5. 中签学生领票；转让限开场前、每票一次，已核销不能转让。验票窗口为开场前30分钟至活动结束，结束时刻不包含。

使用完可重新运行Mock启动入口恢复全新测试场景；不要把本地数据库提交到Git。

## 5. 真实Fabric演示

完整安装与启动按 [Fabric环境指南](LOCAL_FABRIC_SETUP.md) 执行。已部署旧链码的环境须按指南升级，才能使用提前验票规则；从当前源码首次部署则直接包含新规则。

启动real后端并初始化账号后，在实际运行后端的同一环境运行：

```sh
npm run demo:campus
npm run demo:interactive
```

两者通过HTTP与Fabric重建数据，不复制账本、不清空现有记录。可交互场次被使用或过期后，重新运行 `npm run demo:interactive` 补充；加 `-- --new` 强制新增。真实Fabric操作会留存不可删除的历史，因此建议用同学自己的测试网络开始验收。

真实记录应具有Fabric交易ID和区块号；历史区块号通过QSCC查询。报名仍为平台数据库记录。真实E2E脚本会创建并消费独立测试活动，验收后账本保留其历史，不作为预置数据上传。
